# 2026 개선 과정

캡스톤(2025.09) 이후 코드를 다시 점검하면서 찾은 문제를 **현상 → 원인 → 조치 → 검증** 순서로 정리했습니다.
원본(2025)과 개선본(2026)의 전체 차이는 [커밋 비교](https://github.com/SEONGBINJEON/Ploggy/compare/2025-capstone...2026-improved)에서 볼 수 있고, 항목별 목록은 [CHANGELOG](../CHANGELOG.md)에 있습니다.

## 진행 방식
1. **발표자료와 코드 대조**: 발표에서 소개한 기능이 코드에 실제로 있는지 하나씩 확인
2. **원인 분석**: 정적 분석(`flutter analyze`), 모델 파일 그래프 분석, 공공 API를 직접 호출해서 응답 형식 확인
3. **수정**: 원인을 고치고, 같은 문제가 다시 생기지 않도록 단위 테스트를 함께 추가
4. **검증**: 단위 테스트 38개, 정적 분석, 디버그·릴리스 APK 빌드, 웹 빌드. 수정 후 별도 코드 리뷰를 한 번 더 받아 추가로 찾은 10건도 고침

AI 코딩 도구(Claude Code)와 함께 점검하고 수정했습니다.

## 1. AI 신뢰도가 최대 35%로 눌려 보임
- **현상**: 쓰레기 분류 신뢰도가 늘 30%대로 나옴 (발표 화면 "METAL 32.4%")
- **원인**: 모델 마지막 연산이 이미 Softmax인데 앱에서 Softmax를 한 번 더 적용 → 6개 클래스에서 최대 e/(e+5) ≈ 35.2%
- **조치**: 출력이 확률이면 그대로 사용, logits이면 Softmax 적용 (모델을 바꿔도 동작)
- **검증**: 발표 화면 값(32.4/14.0/13.7%)을 역산하면 실제 약 89.5% → 회귀 테스트로 재현·수정 확인
- 자세한 내용: [AI 모델 문서](ai-model.md#5-캡스톤-이후-찾은-문제-신뢰도가-35를-넘지-못함)

## 2. 조깅 중 다른 탭으로 가면 기록이 사라짐
- **현상**: 조깅하다가 쓰레기 탭에서 사진을 찍고 돌아오면 기록이 초기화되고 저장도 안 됨. "달리면서 쓰레기를 줍는" 플로깅의 핵심 흐름이 막혀 있었음
- **원인**: 하단 탭을 바꿀 때마다 이전 화면을 폐기하는 구조 → 위치 구독과 타이머가 함께 종료
- **조치**: 탭 상태를 유지하도록 변경(처음 연 탭만 생성). Android는 포그라운드 서비스로 화면을 끄거나 카메라를 열어도 위치를 계속 받음. 시작 버튼을 두 번 눌러 세션이 겹치거나, 정지 뒤 늦게 도착한 위치가 더해지는 문제도 함께 막음
- **검증**: 정적 분석·APK 빌드, 빌드된 APK에 서비스 권한이 들어갔는지 확인. 실기기 확인은 남아 있음

## 3. 주변 쓰레기통이 지도에 안 뜸
- **현상**: 지도에 쓰레기통 마커가 하나도 표시되지 않음
- **원인**: ① 멜버른 공공데이터 중 **주사기 수거함** 데이터셋을 사용 ② 옛 API 형식(`geometry`/`fields`)으로 파싱 → 현재 응답(`geo_point_2d`)과 맞지 않아 예외가 났지만 화면에는 아무 표시 없음
- **조치**: OpenStreetMap(Overpass API)으로 교체 — 현재 위치 1km 안의 일반 쓰레기통(빨강)과 재활용 수거함(노랑, 받는 품목 표시). 지도에 데이터 출처 표기
- **검증**: 실제 API 호출 결과 멜버른 Flinders St 주변 125곳(재활용 19곳) 확인, 응답 파싱 단위 테스트

## 5. 릴리스 빌드 실패
- **현상**: `flutter build apk --release`가 R8(코드 축소) 단계에서 실패. 원본도 같은 문제로, 디버그 빌드로만 실행해 왔음
- **원인**: TFLite 라이브러리가 참조하는 GPU 옵션 클래스가 의존성에 없음
- **조치**: `proguard-rules.pro` 추가 (GPU 클래스는 무시, TFLite 클래스는 유지)
- **검증**: 디버그·릴리스 APK 빌드 성공 (릴리스 90MB)

## 6. 보안·개인정보
- **현상**: Google Maps API 키가 저장소에 커밋돼 있었고, README가 Firestore 전체 공개 규칙(`allow read, write: if true`)을 안내했으며, 사용자 이메일을 다른 사용자도 읽을 수 있는 문서에 저장
- **조치**: API 키를 `android/local.properties`(깃 제외)로 분리, Firestore·Storage 보안 규칙 작성, 랭킹은 이름과 기록만 담은 별도 컬렉션에서 읽도록 분리
- **검증**: 저장소 전체에서 Maps 키가 없는지 확인, 빌드된 APK에 키가 정상적으로 들어가는지 확인
