# AI 쓰레기 분류 모델

캡스톤에서 제가 맡은 부분입니다. 플로깅 중에 주운 쓰레기 사진을 앱 안에서 바로 분류하고, 멜버른의 3색 분리수거 통 중 어디에 버릴지 안내합니다.

## 1. 문제 정의
- **입력**: 스마트폰으로 찍은 쓰레기 사진 1장
- **출력**: 6종 분류(유리·금속·음식물/유기물·종이·플라스틱·일반) + 버릴 통
- **조건**: 야외에서 바로 써야 하므로 서버 없이 기기에서 동작하고, 앱 용량 부담이 작아야 함

## 2. 데이터
- 처음에는 **TrashNet**으로 시작했지만 정확도가 낮았습니다.
- 실제 거리 사진 기반이고 쓰레기 종류가 다양한 **[TACO](http://tacodataset.org/)(Trash Annotations in Context)** 로 바꿨습니다.
- TACO는 사진 한 장에 쓰레기 위치(바운딩 박스)가 표시된 데이터라서, 박스 기준으로 잘라 **분류용 이미지 데이터**로 가공했습니다.
- 최종 클래스: `glass`, `metal`, `organics`, `paper`, `plastic`, `trash`

## 3. 모델과 학습
| 항목 | 내용 |
|---|---|
| 구조 | 입력 224×224×3 → 전처리(그래프 안에 포함) → **MobileNetV2 (1.00, 224)** → Global Average Pooling → Dense(6) → Softmax |
| 학습 | 데이터 증강, 하이퍼파라미터 튜닝, 10 epoch |
| 결과 | **검증 정확도 약 87%** (목표 85%) |

구조는 배포한 TFLite 모델 파일의 그래프를 기준으로 정리했습니다. 학습 코드는 이 저장소에 없고, 학습된 모델 파일만 들어 있습니다.

<img src="images/training_curves.png" alt="epoch별 학습 손실(왼쪽)과 검증 정확도(오른쪽)" width="760">

학습 손실은 10 epoch 동안 전반적으로 꾸준히 줄었습니다. 검증 정확도는 2~3 epoch에 50% 안팎으로 떨어졌다가 다시 올라, 7 epoch 이후 84~87% 사이를 유지했습니다.

## 4. 모바일 배포
`handout_mobile_20250815_0505/` 폴더에 앱에서 쓰는 파일을 모아 두었습니다.

| 파일 | 크기 | 용도 |
|---|---|---|
| `plogging_224_fp16.tflite` | 4.5MB | 기본 모델 (FP16 가중치) |
| `plogging_224_dynamic.tflite` | 2.5MB | 기본 모델을 못 불러올 때 대체 (동적 범위 양자화) |
| `labels.txt` | — | 클래스 6개 |
| `disposal_map.json` | — | 클래스 → 분리수거 통 매핑 |

**분리수거 매핑** (멜버른 3색 쓰레기통 기준)

| 클래스 | 통 |
|---|---|
| glass, metal, paper, plastic | 재활용 (노란 뚜껑) |
| organics | 음식물·유기물 (초록 뚜껑) |
| trash | 일반 쓰레기 (빨간 뚜껑) |

**앱 안에서의 추론 과정**
1. 사진을 최대 1280px로 줄여서 받음 (분석 속도·업로드 용량 개선)
2. 사진의 EXIF 회전 정보를 반영해 실제로 보이는 방향으로 맞춤
3. 224×224로 줄이고 8비트 RGB(0~255)로 변환
4. TFLite로 추론 → 6개 클래스의 확률
5. 확률 순으로 정렬하고, `disposal_map.json`으로 버릴 통을 정함
6. 1위 신뢰도가 50%보다 낮으면 다시 찍어 보라고 안내

관련 코드: [`image_preprocess.dart`](../lib/services/image_preprocess.dart), [`trash_classification_service_mobile.dart`](../lib/services/trash_classification_service_mobile.dart), [`classification_math.dart`](../lib/services/classification_math.dart)

## 5. 캡스톤 이후 찾은 문제: 신뢰도가 35%를 넘지 못함
- **현상**: 발표 화면의 "METAL 32.4%"처럼 신뢰도가 늘 낮게 나왔습니다.
- **원인**: 모델의 마지막 연산이 이미 Softmax인데, 앱에서 Softmax를 한 번 더 적용했습니다. 이미 확률인 값에 Softmax를 다시 씌우면 값이 평평해져서, 6개 클래스일 때 1위 신뢰도가 최대 e/(e+5) ≈ **35.2%** 를 넘을 수 없습니다.
- **역산**: 발표 화면의 32.4% / 14.0% / 13.7%를 거꾸로 계산하면 실제 확률은 약 **89.5%** / 5.6% / 3.4%였습니다.
- **영향**: Softmax는 순서를 바꾸지 않아서 1위 라벨(분류 결과)은 맞았고, 신뢰도 숫자만 틀렸습니다.
- **조치**: 모델 출력이 이미 확률(0~1, 합 1)이면 그대로 쓰고, logits이면 Softmax를 적용하도록 바꿨습니다. 나중에 모델을 바꿔도 동작합니다.
- **검증**: 버그 재현과 수정을 단위 테스트로 확인합니다. ([`classification_math_test.dart`](../test/classification_math_test.dart))

## 6. 한계와 다음 단계

- 멜버른 현지에서 찍은 사진을 추가해 실제 사용 환경에 맞추기
